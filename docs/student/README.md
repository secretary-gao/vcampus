# 教师查看学生学籍

本功能对接 `feat/course-realistic-model` 的教学班模型（集成基点 `a3483a0`）。

## 使用方法

1. 学生登录后，在选课模块选择一个教学班。
2. 任课教师登录，打开选课模块的“教师工作台”，点击“刷新”。
3. 选择对应教学班，在学生名单中选中学生，点击“查看学籍”；也可以双击学生或按 Enter。
4. 弹窗显示学号、姓名、班级、专业、年级、学籍状态，教师仅可查看。

当前班名单支持按学号或姓名即时搜索，并显示“匹配人数 / 全班人数”。
清空搜索可恢复完整名单，表头排序在筛选后保留。“导出整班名单 CSV”始终导出当前教学班全部学生。

弹窗每次打开或点击“重新加载”时读取最新学籍，并在服务器重新校验授课关系。
学生退掉该教师的全部教学班后，教师不能再通过学号、姓名或旧名单查看其学籍；
如果仍选修该教师的其他课程，则保留查看权限。学生名单需点击“刷新”更新。
刷新后保留当前教学班和搜索条件，切换教学班或修改搜索时清除原来选中的学生。
刷新失败时保留已有名单并明确提示数据可能过期，可以再次刷新；双击空白行不会打开此前选中的学生。

## 关联与权限

学籍服务以实际登录账号确认教师角色，再按以下关系查询：

```text
tblUser.uId → 教师姓名
                 ↓
tblTeachingClass.teacher
                 ↓ teachingClassId + courseId
tblSelectCourse.studentId → tblStudent.studentId
```

以教学班的教师为准，不使用 `tblCourse.teacher` 的兼容字段授权。
同一课程不同老师的班级分别计算权限；选修同一教师多门课程的学生在学籍列表中去重。
教师响应仅包含上述六个字段，不返回一卡通号、登录账号和入学日期，也不能新增、修改或删除学籍。

管理员编辑已有档案时可以更正学号。保存前会同时检查新学号和一卡通号是否与其他学生冲突；
学号修改成功后，数据库通过外键级联同步已有选课记录中的学号。
教师工作台的教学班名单接口同样要求提交当前登录凭据。服务端重新读取真实账号，
只接受状态正常、姓名唯一的教师账号，并始终使用数据库中的教师姓名查询本人教学班；
客户端伪造姓名或角色不能读取其他教师名单。
按学号或姓名查询时，授课关系与查询条件在同一条数据库查询中判断，不再先读取整份学籍名单后筛选。
更换教学班任课教师后，新旧教师的学籍查看权限在下次请求时按最新授课关系判断。

每次学籍请求都核对数据库中的最新账号状态，客户端提交的状态不作为依据。
已禁用、待审核或状态异常的账号不能访问学籍；恢复为“正常”后可以重新请求。
此检查适用于学籍模块的学生、教师和管理员操作。

当前课程模型使用姓名关联任课教师，教师账号姓名须与教学班教师字段一致。
沿用学籍模块已有保护：如果存在同名教师账号，不授予学籍查看权限，需管理员核对账号与授课信息。

## 数据库前提

需配置 `Server/db.properties`，并具备用户表、学籍表及新版课程表。
新环境的课程初始化方法见 [课程模块说明](../course/README.md#5-数据库设计与初始化)。

已有 Course 1.0 数据库，按顺序执行仓库提供的升级脚本：

```sql
SOURCE sql/course/migration_course_teaching_class.sql;
SOURCE sql/course/migration_course_requirement_group.sql;
```

若旧用户表缺少 `uStatus`，先执行 `sql/migration_add_user_status.sql`；
若其状态枚举缺少“待审核”，执行 `sql/migration_add_pending_status.sql`。
如果数据库来自旧版演示数据，执行 `sql/migration_student_account_role.sql`，修复
`12345678` 同时作为教师账号和学生学籍账号的历史冲突；修复后该学生账号密码为 `123456`。
本功能无需增加学籍字段或导入演示数据；课程表缺失时会显示初始化提示。

## 验证

在项目根目录执行，使用 JDK 21 和项目自带 JDBC 驱动：

```powershell
.\build.bat
java -cp "bin;lib/mysql-connector-j-9.7.0.jar" vcampus.server.srv.StudentPermissionTest
java -cp "bin;lib/mysql-connector-j-9.7.0.jar" vcampus.client.biz.StudentCourseEnrollmentTest
```

第一个测试不访问数据库，验证服务端角色权限。
第二个测试需本地 MySQL，自动申请独立的本机端口，无需停止正在运行的 vCampus 服务器。
它自行启动统一请求处理服务，创建随机标识的临时账号、学生、课程和教学班，
经真实客户端验证同课不同教师、选课可见、跨教师不可见、字段范围、只读权限、
状态更新、多课去重、退课撤权、重新选课、账号禁用/待审核、同名教师和任课教师变更。
结束后只清理本次创建的记录。

界面验收可检查：未选学生时按钮不可用，加载中仍可关闭弹窗，失败后可重新加载，
退课后旧名单无法继续查看学籍，刷新保留教学班，Enter 可打开所选学生学籍，
搜索与排序能配合使用，刷新失败后可重试，空白行双击不弹出学籍。
学生账号由管理员新增学籍档案时自动创建，账号使用学籍中的“用户账号”，初始密码为 `123456`。
学生端不提供自助注册入口；教师和管理员账号仍按用户模块的注册审核流程处理。
